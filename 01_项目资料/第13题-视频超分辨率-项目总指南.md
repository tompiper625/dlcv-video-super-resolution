## 1. 研究问题与贡献

给模型三张连续低清帧 `[前帧, 中心帧, 后帧]`，输出**同一时刻的高清中心帧**。例如从三张 `224×128` RGB 帧预测一张 `448×256` RGB 帧。对视频滑动这个窗口，可以逐帧恢复，输出帧率与原视频相同。

以栏杆为例。镜头横移时，同一根栏杆会落在不同的像素位置，邻帧可能保留中心帧缺失的边缘细节。直接叠加这些位置可能产生双边。若前一帧中的栏杆又被行人挡住，前帧的对应位置就只剩衣服纹理。此时即使估计出正确的背景位移，也只能从后帧补栏杆细节。**位移决定内容能否对齐，遮挡决定内容是否存在。**

> **主问题**　在轻量三帧 2× 超分中，当某个区域只在一个邻帧被遮挡时，按对齐置信度降低该邻帧的权重，能否减少这个区域的重建错误，同时保留另一个邻帧的细节？这个效果如何随位移变化？

| 假设 | 固定什么、比较什么 | 看什么 |
|---|---|---|
| H1　相邻帧有时能补细节 | 相同 CNN、数据与训练预算，比较单帧 B1 和直接三帧 B2 | 全图 PSNR/SSIM、纹理局部图。无遮挡时也要看到底有无收益。 |
| H2　对齐改变不同位移下的收益 | 同一遮挡等级，比较未经对齐的 B2 和对齐的 B3 | 每档位移的 `PSNR(B3) − PSNR(B2)`，结合对齐图解释失败。 |
| H3　置信度加权能减轻单侧遮挡误差，收益可能有代价 | 同一位移和同一正向光流，比较 B3 与 B4 | 单侧遮挡区域的 MAE、两邻帧均可见区域的 MAE、全图 PSNR，以及跟单帧 B1 的差距。 |

三帧输入、光流对齐和光流一致性筛选都有文献先例。项目贡献在于**固定轻量模型与训练协议，独立控制位移与遮挡，按区域检验邻帧筛选的收益和代价**。这属于「时序信息到底贡献多少」里的三帧滑窗问题。[BasicVSR][basicvsr] · [Upscale-A-Video][upscale]

**Pre 一句话。** 我们分别控制帧间位移和遮挡，测量相邻帧什么时候能帮轻量模型恢复细节，以及按置信度融合能否减少遮挡引起的重影。

## 2. 已有证据与正式实验要验证的事

CPU 预实验用了 10 张训练图、8 张独立测试图，测试图取出 24 个裁块，生成 `2 档位移 × 2 档遮挡` 的合成三帧。用共享的局部线性超分模型和 scikit-image TV‑L1 光流。结果表中的两个数字依次为普通对齐和置信度加权。

| 单侧遮挡条件 | 遮挡区域 MAE，越低越好 | 整帧 PSNR，越高越好 |
|---|---|---|
| 位移 1.5 个低清像素 | `0.01345 → 0.01290`，约降低 4.1% | `36.48 → 36.45 dB` |
| 位移 7.5 个低清像素 | `0.01342 → 0.01313`，约降低 2.2% | `36.26 → 36.09 dB` |

这两组遮挡条件下，单帧基线的整帧 PSNR 为 `36.77 dB`，遮挡位置的 MAE 也低于自动加权。无遮挡、位移 7.5 像素时，加权的 PSNR 从 `36.62` 降到 `36.38 dB`。使用真实遮挡掩码屏蔽坏邻帧的诊断在两档位移都得到了比自动加权更低的局部误差。正式实验因此要一起看**局部错误、可见细节和整帧质量**。这些预实验数字仅用于提出假设，正式报告主表用 CNN 重测。[预实验脚本](vsr_pilot/run_pilot.py) · [480 行测量结果](vsr_pilot/results.csv)

用目标环境从项目根目录运行 `python vsr_pilot/run_pilot.py` 可以重跑预实验；它依赖 `numpy`、`scipy`、`scikit-image` 及脚本列出的本地样图，会重写同目录的 `results.csv`。正式实验的样例、训练入口和依赖由三人按下文实现和联验。

## 3. 数据怎么做

### 3.1 公开视频

- **主选 Vimeo‑90K Septuplet。** 每个样本 7 帧，分辨率 `448×256`。沿用官方训练和测试列表，从训练集做验证划分。训练轮次只需要选定的子集，原始完整版约 82 GB。磁盘或下载受限时可改用 **REDS 的部分清晰序列**。选定一套数据并保存样本清单。先跑约 30–50 个短序列，正式规模可从约 1,000 训练、100 验证、200 测试短序列起步。长视频则分别记录独立视频数和抽取窗口数。[Vimeo‑90K][vimeo] · [REDS][reds]
- 按可获得的原始视频 ID 或最高层片段 ID 分组后划分，防止相邻窗口落在不同划分。对每组划分记录来源、相对文件路径和 ID。检查同一分组没有跨划分；若缺少原始视频 ID，在报告说明所用分组粒度。
- 用带抗混叠的双三次插值对高清 RGB 帧做 2× 降采样。训练可用 `64×64` 低清裁块及对应 `128×128` 高清目标。低清从 `(y,x)` 裁剪时，高清从 `(2y,2x)` 裁剪。三帧与高清目标共享裁剪和翻转。整帧评估统一像素范围、退化配置、边缘裁剪及颜色空间。

### 3.2 受控集 | 4 档位移 × 3 档遮挡

从**未参与训练或调参**的来源选约 50 张独立底图，每个原视频优先取一张。每张底图固定中心高清裁剪，在同一份中心目标上生成 12 个条件。

| 因素 | 默认水平 | 生成约定 |
|---|---|---|
| 位移，单位为低清像素 | `0 / 1.5 / 3.5 / 7.5` | 对应高清 crop 偏移 `0 / 3 / 7 / 15` 像素。每张底图选水平或垂直方向，前后帧相反，方向跨条件固定。用更大底图直接移动裁剪窗，保留相同的半像素采样相位。0 位移用作检查。 |
| 邻帧遮挡，按中心有效区计算 | `0% / 10% / 25%` | 以两张邻帧的遮挡掩码**并集占比**定义档位。在中心坐标系放两个掩码，再随对应邻帧的背景位移映射到邻帧作图。可以让掩码部分重叠，确保有足够面积属于仅一帧被挡；同一底图、同一遮挡档的掩码与纹理跨位移复用。记录实际并集覆盖率和单侧覆盖率。 |

1. 从有足够边距的高清底图渲染三帧，只在邻帧中合成遮挡物，然后统一降采样。用同一种固定有效内裁剪评估所有位移档。变化条件之间的 `hr_center` 必须逐像素相同。
2. 保存两张掩码 `mask_prev` 与 `mask_next`，都在高清中心帧坐标系内。`mask_prev XOR mask_next` 是主评估区域，`AND` 是同时被挡区域，两张都为假是均可见区域。正式模型只接收低清帧和从低清帧估出的置信度。另做诊断时才把真实掩码用于输入。
3. 先存一个小样例供联调：一张已知位移的三帧、一张只有前帧被挡的三帧、对应高清中心和掩码。眼睛看一遍拼图，再检查掩码位置、裁剪及帧序。训练主线用公开视频，受控测试集不参与调参。

这种构造隔离了平移和前景遮挡。真实素材还可能有旋转、手持抖动、运动模糊和压缩；在报告讨论实际覆盖到的条件。

### 3.3 自摄数据

拍 6–9 段，每段约 5–10 秒，涵盖静态细纹理、慢速横移、前景移动遮挡。保留高清原片，记录三类场景及抽帧规则，按同一流程生成低清输入。原片可用于定量和定性对比。无准确遮挡掩码时写清选看的局部区域，定量结果以全图为主。自摄结果按视频单列，解释受控实验中的现象是否能复现。

## 5. 五组方法怎么实现

| 编号 | 处理 | 用途 |
|---|---|---|
| **B0** | 中心帧用双三次插值放大 2× | 无训练参照 |
| **B1** | 把中心 LR 帧复制三份，拼成 9 通道送入 CNN | 逐帧参照，CNN 参数量一致 |
| **B2** | 拼接原始前、中心、后帧后送入 CNN | 测额外帧的贡献 |
| **B3** | 将前后邻帧对齐到中心坐标，再拼接 | 测光流对齐的作用 |
| **B4** | 对每张对齐后的邻帧按自身置信度和中心帧混合，再拼接 | 测不可靠邻帧降权的作用 |

**B 的网络。** ESPCN 风格 `9 → 64 → 64 → 64 → 64 → 64 → 12`，全部 `3×3`、步幅 1、padding 1；中间 ReLU，最后接 `PixelShuffle(2)`，约 16 万可训练参数。可统一采用对双三次中心帧预测残差的形式，采用后 B1–B4 共用。建议起点为 L1、Adam、`lr=1e-3`、`batch=4–8`。在实际设备跑约 100 步，按显存和吞吐冻结正式预算、种子与验证频率。B1–B4 统一数据、模型、步数、裁块和增强规则，按同一验证指标选 checkpoint。关键组有余量再追加相同配对种子。[ESPCN][espcn]

**C 的对齐。** 默认先试 OpenCV Farnebäck。对每个中心坐标 `x`，从邻帧的 `x+f(x)` 采样，其中 `f` 为中心到邻帧的光流。用已知平移样例先检查方向。B3/B4 使用同一正向 warp 和越界规则，越界回填中心帧。反向光流记作 `g`，在对应点采样，往返误差为 `e(x)=||f(x)+g(x+f(x))||`。B4 对有效位置取 `w=exp(-(e/τ)²)`，其邻帧输入为 `w×对齐邻帧+(1−w)×中心帧`。前帧与后帧分别估权重，越界处 `w=0`。`τ=1` 个低清像素作为起点；如需选择 `0.5/1/2`，用独立验证数据和小预算比较，冻结后再跑正式模型。[OpenCV 光流][farneback]

**联调约定。** 光流优先从整张低清帧计算，对齐和加权后再用相同坐标裁块，避免在 B3/B4 的小裁块边缘额外丢对应点。若缓存，分别记录数据版本、帧对 ID、分辨率、流程参数和流方向。空间翻转与裁剪施加在对齐后的结果和目标上；如果在增强后重算光流，也记录并统一策略。计端到端速度时要包含实际光流、warp 及网络，缓存训练结果可另外计时。

## 6. 怎么算分、怎么得出结论

| 输出 | 计算口径 | 报告用途 |
|---|---|---|
| 公开、自摄主表 | RGB `[0,1]` 下统一算 PSNR/SSIM，统一有效范围及 `data_range=1`，先逐帧后按独立视频汇总。记录聚合方式。 | B0–B4 主结果，公开与自摄分别展示。 |
| 受控区域表 | 按「仅一个邻帧被挡」「两邻帧都被挡」「两邻帧都可见」计算 RGB MAE，区域为空记 `NA`，同时记有效像素和有效底图数。 | 对比普通对齐、加权和单帧，判断局部变化及可见区代价。 |
| 两张 `4×3` 热力图 | `PSNR(B3)−PSNR(B2)` 越大说明对齐越有利；`MAE(B4)−MAE(B3)` 在单侧遮挡区越小越好，无遮挡列为 `NA`。 | 回答 H2/H3，配局部放大图并给出对应全图表现。 |
| 失败图、速度与视频 | 同一位置、同一显示尺度，注明方法、位移和遮挡区域。耗时在相同设备、输入、预热次数下测，GPU 前后同步。 | 记录误对齐、混入遮挡纹理、过度丢弃邻帧和推理成本。 |

逐样本结果至少包含 `run_id,method,dataset,source_id,sample_id,displacement_lr,occlusion_level,psnr,ssim,mae_one,mae_both,mae_visible`。同一底图的多个条件和同一视频的相邻帧有关联。可对处理差值按底图或视频做配对 bootstrap；简单汇报也应给出独立样本数及差值。PSNR/SSIM 反映帧画质。若只看连续播放，闪烁作为定性观察；要定量声称时序稳定性改善，需要另设时序指标与计算口径。

**结果判读。** 若加权改善单侧遮挡的 MAE，但整帧或可见区域变差，报告收益和代价。若 B4 仍落后于 B1，也要如实报告。诊断优先选择一个：用合成的真遮挡掩码替代置信度，检查筛选是否有潜力；或用已知平移替代估计光流，检查对齐误差。二者都是辅助定位问题的对照，和正式输入分开标注。

## 7. 分工、依赖与验收

**A 做数据，B 搭网络并跑完所有正式训练，C 做改进与结果分析。** 三人在租卡前并行准备。C 负责 B3/B4 的实现与验证，正式训练和统一评估都由 B 在同一台租用机器上执行。

| 成员 | 租卡前负责什么 | 正式实验及汇报交付 |
|---|---|---|
| **A · 数据** | 固定公开数据划分，做 LR/HR 配对、4×3 受控集和自摄测试。先发一组可离线读取的合成样例，检查中心 HR 一致、单侧遮挡只改一张邻帧。提前备好实际使用的数据、清单、体积及传输路径。 | 交数据代码和清单；录制时用自己的样图讲问题动机、配对和位移遮挡设计。 |
| **B · 网络与统一训练** | 实现 B0–B2 和共享训练入口，支持 C 接入三帧预处理。用 CPU 让 B1–B4 各跑几步，检查输入输出、损失、保存加载和统一评估。准备各组配置与顺序命令。 | **独自执行 B1–B4 全部正式训练**。同机跑 B0–B4 的评估和计时，导出后交 C；录制时讲小 CNN、基线和统一训练协议。 |
| **C · 改进与分析** | 用 CPU 实现 B3 光流对齐、B4 置信度加权和评估脚本。用已知位移、越界和单侧遮挡样例检查 warp 与权重；写好正式命令并列清需要导出的预测、权重图和指标。 | 拿 B 导回的结果在本地出主表、4×3 热力图、自摄对比和失败例；录制时讲改进方法、局部收益与整帧代价。 |

**租卡前验收。** 同一小样例能读出三帧、高清中心目标和掩码；四组都能训练几步、存取 checkpoint 和输出 2× 预测；C 的评估能按 sample_id 找齐预测、真值和掩码。B1–B4 共用数据、网络、训练步数和验证规则。B0 是插值参照，直接进入评估。

**正式实验验收。** B 交四组可加载的 checkpoint、日志和配置，以及五组指标、耗时和代表性预测。C 能靠这些产物在本地画主图。A 或 C 可用干净解压目录复跑最小样例。录制顺序保持 A → B → C，各讲自己完成的工作。

<a id="zip-handoff"></a>

## 8. 源码 ZIP 与一次租卡流程

1. **租卡前交 ZIP。** A 发数据代码和样例，C 发对齐、加权和评估模块，B 加到自己的训练目录并联调。正式数据与大缓存另传。先看数据包大小、上传速度与远端磁盘容量。有可预置的数据盘时提前传；没有时备好能直接解压的实验子集。先用少量样本比较光流预计算上传与远端即时计算的总时间。
2. **开机后短测。** 确认 CUDA、依赖、输入数据和输出路径。用 B1、B4 按计划的裁块和 batch 短跑，测显存和每百步耗时。B4 的实测时间包括读取及光流流程。按耗时统一确定四组预算，留出验证、评估、导出和下载时间。发现预算超出时，在正式开跑前统一缩小数据量或步数。
3. **排队训练 B1 → B2 → B3 → B4。** 每组独立保存日志和 checkpoint，记录配置、数据清单、种子、实际步数和验证选点规则。中断后从最后成功的 checkpoint 或未完成的组继续。训练结束，在同一台机器统一评估 B0–B4。速度测试统一分辨率、batch 与计时口径，端到端耗时算入 CPU 光流和重采样。
4. **先下载、核对，再停止计费。** 确认权重、日志、配置、主 CSV 和选定的预测与权重图在本地可读，C 已能拿这些结果作图。按租用服务规则停止实例，并确认是否还有单独计费的磁盘。最终源码 ZIP 放可复跑代码、配置、精简结果和获取数据与权重的说明。

交接时附三行：本包包含什么、下一位先跑哪条命令、数据或权重从哪里取得。三人在开工时约定联调日期与正式开跑日期。

## 9. 常见问题先查哪里

| 现象 | 先核对 | 主要联系人 |
|---|---|---|
| 同一底图不同条件的中心图变了 | 比较中心 HR 是否逐像素相同，检查分支是否误用了不同裁剪或把遮挡画到中心帧。 | A |
| loss 不下降、输出尺寸或颜色不对 | 先用极小样本拟合；检查 RGB/通道顺序、数值范围、LR 与 HR 裁剪倍率，以及拼成 9 通道的顺序。 | B，A 核对数据 |
| warp 后边缘偏得更远 | 用已知平移和十字标记确认方向、`dx/dy` 轴顺序、有效坐标和越界回填。检查用的是中心到邻帧的采样映射。 | C |
| B3/B4 明显慢于 B2 | 分开测光流、warp 与网络。训练可缓存流或对齐结果，确认数据与参数版本匹配。正式端到端计时包含预处理。 | C、B |
| 加权局部好、整帧差 | 查看权重图和可见区域 MAE，优先对照真实遮挡掩码或已知位移，检查是否误压了可用的邻帧。 | C，B 复跑训练 |
| 重跑数字不一致 | 对比所用 ZIP、划分 ID、配置、种子、checkpoint、裁剪与光流版本。先重跑同一固定样例再扩大排查。 | 相应阶段的作者 |
| 队友解压后找不到数据或脚本 | 从干净目录按 README 检查依赖，相对路径和运行目录写清楚；大文件的获取位置查数据或 checkpoint 清单。 | 发包人和文件作者 |

## 11. 最终交付与评分对照

- **源码 ZIP。** README 记录依赖版本、最小样例命令、准备数据方法、正式训练与评估入口。附配置、数据清单、结果 CSV、必要的图和实验编号。权重索引标出获取位置及配套配置。
- **报告。** 课程建议约 5 页，参考文献另计，推荐 CVPR 格式。写清问题和假设、方法、数据、对照、结果、局限与个人贡献。选题的难度和新颖性用受控实验解释，代码的可复现性用实际命令和产物证明。
- **Pre。** 提交录制视频和幻灯片，建议 4–4.5 分钟，最长 5 分钟。可以按 **A 约 1 分 10 秒**讲任务和受控数据，**B 约 1 分 10 秒**讲 CNN 和 B0–B2，**C 约 1 分 55 秒**讲 B3/B4、热力图、失败例和结论。A 用自己的数据图，B 用自己的基线图，C 用自己的评估图，总计约 4 分 15 秒。
